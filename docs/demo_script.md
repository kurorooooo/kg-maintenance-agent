# デモ台本（約10分）

## 事前準備（デモ30分前）

1. Docker Desktop を起動し `docker compose up -d`。http://localhost:7474 にログイン（neo4j / maintenance-demo）
2. Claude Desktop を起動（search_manual がモデルを先読みする。起動後 10 秒待つ）
3. Claude Desktop のプロジェクトに docs/prompt.md のシステムプロンプトが入っていることを確認
4. ウォームアップとして「P-301 の型式は？」を1回投げ、ツールが動くことを確認する
5. Neo4j Browser に queries/paths.cypher を開き、各クエリをお気に入りに登録しておく
6. 画面配置：左に Claude Desktop、右に Neo4j Browser

## 導入（1分）

> 「A工場という架空の工場を用意しました。3ライン12設備、部品、故障モード、過去2年の作業報告80件、保全マニュアル5冊です。御社の設備台帳・作業報告・マニュアルをこの形につなぐと、こういうことができます。」

docs/model.md のグラフモデル図を見せる。「故障モードが真ん中にいて、症状から入り、部品や型式で同型機へ横断し、作業報告と手順で過去の対応に降りる」と説明。

## グラフを見せる（1分）

Neo4j Browser で paths.cypher の「P-301 周辺のサブグラフ」を実行。

> 「3号ラインの冷却ポンプ P-301 です。型式 CP-200、部品 8 点、故障モード 7 種、作業報告 16 件がつながっています。」

## 質問1（2分）

Claude に入力：
> 3号ラインの冷却ポンプP-301で振動が上がっている。考えられる原因と過去の対処は？

見せるポイント：
- 原因候補が「過去事例 6 件」のように件数付きで確度順に並ぶ
- 根拠節に作業報告 ID、手順 ID、手順書チャンク ID（CH-cp-200-002、p.1「2.1 振動・異音の確認」）が出る
- 右画面で paths.cypher の「Q1 根拠」を実行し、同じパスが光ることを示す

> 「この答えはマニュアルの何ページから来ているか、どの作業報告から来ているかが全部 ID で示されます。幻覚かどうかを人が検証できます。」

## 質問2（2分）

> 同じ型式のポンプで同じ症状が出た事例は他ラインにもある？

見せるポイント：
- 第1ラインの P-101 で 4 件、第2ラインの P-201 で 1 件が出る
- 右画面で「Q2 根拠」を実行。P-301 → CP-200 ← P-101 の横断パスを見せる

> 「文書検索（RAG）だけだと、P-301 のマニュアルや報告書は見つかっても、別ラインの同型機の報告書は『P-301』と書いてないので出てきません。グラフなら型式を経由して横断できます。」

## 質問3（2分）

> その対処に必要な部品の在庫と納期、対応できる技術者は？

見せるポイント：
- 部品 3 点の在庫と納期、サプライヤー
- 資格「回転機械整備」を持つ技術者と PR-001 の実施実績。第3ラインの真壁・大槌が第一候補
- 右画面で「Q3 根拠」

> 「原因を当てるだけでなく、次の行動まで一気通貫で出ます。」

## 質問4（1分）

> 直近1年でベアリング起因の停止が多い設備はどこ？

見せるポイント：
- P-301 が 3 件 935 分で最多、同型 CP-200 の 3 台で半数以上
- 「集計もグラフで答えられる。属性（category=bearing）と日付でフィルタしているだけ」と説明

## 締め（1分）

docs/next_steps_onepager.md を見せる。

> 「今日見せたものは合成データですが、御社の設備台帳・作業報告・マニュアルで同じものを 2〜4 週間で作れます。紙や Excel のままでも、まず台帳と作業報告の 2 つをつなぐところから始められます。」

## 想定問答

| 質問 | 答え |
| --- | --- |
| うちのデータは Excel と紙だが | 設備台帳と作業報告の Excel があれば初版は作れる。マニュアル PDF は LLM でチャンク化して部品・故障モードに紐づける（今日の手順書と同じ方式） |
| ベクトル検索とグラフの違いは | ベクトルは「どこから入るか」を決めるだけ。答えの中身（過去事例、部品、技術者）はグラフの構造から取るので、根拠が ID で示せる |
| 書き込みはできるのか | 今日のデモは読み取り専用。作業報告の自動登録は次フェーズ。人の承認を挟む設計にする |
| オンプレで動くか | Neo4j と埋め込みモデルはローカルで動いている。LLM 部分は Claude の API を使うが、オンプレ LLM への置き換えも可能 |
| 応答が遅い | 検索→Cypher→回答の 3 段階で 20〜30 秒。本番ではよく使う質問をテンプレート化して短縮できる |
