# 御社データでの構築手順（2〜4週間）

今日のデモと同じ構成を、御社の実データで再現する手順。自作コードはデータ変換・投入・埋め込みの 3 スクリプトで、Neo4j と Claude は既製品をそのまま使う。

## 入力データ

| データ | 御社での所在（想定） | 最低限必要な列 |
| --- | --- | --- |
| 設備台帳 | 設備管理システム、Excel | 設備ID、設備名、型式、ライン／工程、設置年 |
| 部品構成・在庫 | 購買／資材システム | 型式、部品名、部品番号、在庫数、標準納期、仕入先 |
| 作業報告 | CMMS、日報、Excel、紙 | 日付、設備ID、症状、原因（故障モード）、対処、担当者、停止時間 |
| 手順書・マニュアル | PDF、Word | 本文（ページ単位でチャンク化） |
| 技術者・資格 | 人事、ライン台帳 | 氏名、所属、保有資格 |

紙の作業報告は OCR＋LLM で「設備・症状・原因・対処」を抽出して CSV にする。故障モードの表記ゆれは LLM で正規化する。

## スケジュール

| 週 | 作業 | 成果物 |
| --- | --- | --- |
| 1 | データ棚卸し、グラフモデルの御社向け調整、台帳・部品・技術者の投入 | model.md、Neo4j 上の設備グラフ |
| 2 | 作業報告の変換（表記ゆれ正規化、故障モード辞書作成）と投入 | 故障モード辞書、作業報告ノード |
| 3 | マニュアル PDF のチャンク化・埋め込み・部品／故障モードへの紐づけ、代表質問の定義 | Chunk ノード、質問テンプレート |
| 4 | Claude 接続、プロンプト調整、現場担当者による評価、根拠パスの可視化 | 評価結果、デモ環境 |

## 構成（デモと同じ）

- Neo4j（オンプレ Docker またはクラウド）。読み取り専用で Claude に接続
- mcp-neo4j-cypher（既製）＋ search_manual（埋め込み検索、ローカルモデル）
- Claude Desktop または社内チャット画面
